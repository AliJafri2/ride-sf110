# Build Notes — SBMLReader2 (SF110 #34)

## How the original Ant build worked

The project was built with Apache Ant using a `build.xml` file. It compiled Java 1.6 source
code with iso-8859-1 encoding. The source layout already followed Maven conventions, with
code in `src/main/java` and resources in `src/main/resources`.

All external dependencies were stored as JAR files in a `lib/` directory. There was also a
`test-lib/` directory, but it was empty. JUnit 4.11 was referenced from a shared `../lib/`
parent directory.

The project had no hand-written unit tests. The only tests present were auto-generated by
EvoSuite and stored in `evosuite-tests/`. The original `build.xml` had two bugs in the
`evosuite-test` target that prevented these tests from actually running (wrong dependency
target and wrong fileset directory). After fixing those bugs, the Ant EvoSuite tests ran
with 15 tests total, 13 passing and 2 pre-existing errors.

## What we did for the Maven conversion

The migration was straightforward because the source layout already matched what Maven expects.

We created a `pom.xml` that compiles the same 6 source files with the same Java 1.6 target
and iso-8859-1 encoding. Five of the compile dependencies are not available on Maven Central,
so we placed them in a project-local Maven repository (the `repo/` directory). This means the
build works on a fresh checkout without any extra setup. JUnit 4.11 is the only dependency
pulled from Maven Central.

The 6 EvoSuite test files were copied from `evosuite-tests/` into `src/test/java` so Maven
runs them as part of `mvn clean test`. The `@RunWith(EvoSuiteRunner.class)` annotation and
all EvoSuite imports (Sandbox, Properties) were removed from each file because the EvoSuiteRunner
class is incompatible with Maven Surefire. The actual test methods are standard JUnit 4 and
run correctly without the custom runner. This is the same approach used in the httpanalyzer
and javaviewcontrol migrations.

No application source code was changed.

## Build result

Running `mvn clean test` compiles successfully and runs 14 tests across 5 test classes
(the 6th class, SBMLReaderPlugin2EvoSuiteTest, is empty and gets skipped by JUnit).
12 tests pass and 2 have pre-existing errors:

- `SBMLGraphReaderEvoSuiteTest.test2` — tries to parse an empty XML stream, fails with IOException
- `SBMLFilterEvoSuiteTest.test0` — calls into native libSBML which requires the `sbmlj` shared
  library to be installed on the system (not available in a normal build environment)

Both errors existed under the Ant build as well. The build completes with `BUILD SUCCESS`
because `testFailureIgnore` is set to `true` in the surefire plugin configuration.
